# Publication and trust boundaries

## The assistant can

With a connected MCP Public Ulule and the user's authorization, the assistant can
create or update a proposal, complete an unpublished project draft, set its goal,
add rewards and images, and prepare news as a draft. It can also prepare all of
this as text when no MCP connection is available.

## The assistant cannot

The assistant cannot publish a campaign, guarantee proposal acceptance, bypass
moderation, guarantee a funding result, create facts or evidence, or assume an
MCP connection exists. It must not expose tokens or access another user's data.

## Required language

Use **MCP Public Ulule** for the service. Never use “Ulule AI assistant”,
“assistant IA Ulule”, “Ulule's assistant” or an equivalent suggesting that
Ulule provides the user's conversational assistant.

Say:

> Your AI assistant can use the MCP Public Ulule to prepare an unpublished draft
> on your behalf.

Do not say:

> Ulule's AI assistant will publish your campaign.

Every final handoff must state, in the user's language, that the campaign is
never published automatically.

## Status and promises

- Do not call a proposal a project until the tool returns a `project_id`.
- Do not call an unpublished project a live campaign.
- Do not promise that Ulule will accept a proposal.
- Do not promise a processing or moderation deadline.
- Do not imply that a draft news item was sent.
- Do not promise automatic MCP discovery, installation or connection.
- Do not write unapproved personal, financial or project information.

## User control

Before creating a proposal and before every write, show a compact summary and
obtain the user's explicit approval. Explain that completing all required
proposal fields automatically sends the proposal to Ulule for review. At
handoff, list what was written, what remains uncertain and what the user must
verify. The user reviews and completes the project and Ulule
moderates it before it can be published.
